# KyivWeather — демо-проєкт прогнозу погоди (ASP.NET Core + EF InMemory + Chart.js + ngrok)

Невеликий веб-сервіс, який показує погоду в Києві: графік температури та ймовірності опадів і таблицю на 7 днів.  
Дані подаються **ніби з бази даних**: під час першого запуску бекенд один раз отримує прогноз з Open-Meteo і зберігає його в «БД» (EF Core InMemory).  
Фронтенд читає **лише** з цієї «БД».  
Для доступу ззовні використовується **ngrok**, який створює публічний HTTPS-URL до локального сервера.


## Перенесення на справжню базу даних 
// було:
builder.Services.AddDbContext<AppDb>(o => o.UseInMemoryDatabase("weatherdb"));

// стало:
builder.Services.AddDbContext<AppDb>(o => o.UseSqlite("Data Source=weather.db"));

## Стек технологій
- **ASP.NET Core (.NET 8/9)** — мінімальне API в одному файлі `Program.cs`
- **EF Core InMemory** — імітація бази даних у пам’яті процесу
- **Open-Meteo API** — джерело початкових метеоданих (без API-ключа)
- **Chart.js** — візуалізація графіка на фронтенді
- **ngrok** — публічний доступ до локального сервера
- **CORS** — відкрито лише `GET`, щоб зовнішні сайти могли читати дані

---

## Як працює
1. **Ініціалізація даних.**  
   При першому старті застосунок перевіряє «БД». Якщо вона порожня — один раз звертається до Open-Meteo, забирає ~72 години почасового прогнозу та зберігає у пам’яті.
2. **API.**  
   Ендпойнт `GET /api/forecast` більше не ходить у зовнішнє API, а віддає дані **з БД**, у форматі, сумісному з Open-Meteo (`hourly` + агреговане `daily`).
3. **Фронтенд.**  
   `wwwroot/index.html` робить `fetch('/api/forecast')`, будує графік (дві осі: °C та %) і таблицю на 7 днів.  
   Є невелика «адмінка» для локальних тестів: можна додавати записи або очищати «БД» (POST/DELETE доступні лише з цього ж origin).
4. **Публічний доступ.**  
   Локальний сервер проброшується через **ngrok**, який надає зовнішній HTTPS-URL.
